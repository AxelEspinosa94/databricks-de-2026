# 🇺🇸 ENGLISH VERSION

# 1. Structured Streaming Architecture (Advanced)

## 1.1 Micro‑Batch vs availableNow vs once
- **Micro‑batch**: default mode; processes data in small batches every trigger interval.  
- **availableNow**: processes *all* available data once, then stops; ideal for backfills.  
- **once**: processes exactly one batch and stops; used for deterministic pipelines.

## 1.2 Event‑Time vs Processing‑Time
- **Event‑time**: time embedded in the data (e.g., timestamp column).  
- **Processing‑time**: time when Spark processes the record.  
- Event‑time enables correct late‑data handling and watermarking.

## 1.3 Watermarking
- Defines how long Spark waits for late data.  
- Enables state cleanup in aggregations and joins.  
- Example: `withWatermark("event_time", "10 minutes")`.

## 1.4 Stateful vs Stateless Operations
- **Stateless**: filters, simple transforms, projections.  
- **Stateful**: aggregations, deduplication, streaming joins.  
- Stateful ops require checkpointing and state store.

## 1.5 Streaming Joins
- Stream‑stream joins require watermarks on both sides.  
- Stream‑static joins are simpler and common in pipelines.

## 1.6 Streaming Aggregations
- Requires watermarking.  
- Spark maintains state per key until watermark expires.

## 1.7 Streaming Deduplication
- Uses state store to track seen keys.  
- Requires watermark to clean old keys.

# 2. Auto Loader (cloudFiles)

## 2.1 Schema Inference
- Auto Loader infers schema automatically from incoming files.  
- Supports incremental schema evolution.

## 2.2 Schema Evolution
- Handles new columns automatically.  
- Can enforce strict or permissive modes.

## 2.3 File Notification Mode
- Uses cloud events (S3, ADLS, GCS).  
- Most scalable and cost‑efficient.

## 2.4 Directory Listing Mode
- Lists files directly from storage.  
- Simpler but less scalable.

## 2.5 Handling Corrupt Files
- Auto Loader can quarantine corrupt files.  
- Configurable via `cloudFiles.allowOverwrites` and error handling options.

## 2.6 Auto Loader Checkpoints
- Stores progress, schema, and metadata.  
- Enables exactly‑once ingestion.

## 2.7 Best Practices
- Use notification mode.  
- Use schema hints.  
- Avoid small files.  
- Use partitioning wisely.

# 3. Delta Lake + Streaming

## 3.1 Writing Streams to Delta
- Delta provides ACID guarantees for streaming sinks.  
- Supports exactly‑once semantics.

## 3.2 Reading Delta as a Streaming Source
- Delta tables can be read as streams using `readStream.format("delta")`.

## 3.3 Streaming MERGE Patterns
- Used for upserts in streaming pipelines.  
- Requires `foreachBatch` or Delta CDF.

## 3.4 Upserts in Streaming Pipelines
- Combine Auto Loader + MERGE for CDC ingestion.  
- Ensures idempotency.

## 3.5 Change Data Capture (CDC)
- Delta CDF exposes row‑level changes.  
- Useful for downstream syncs.

## 3.6 Delta as a Sink with Exactly‑Once Guarantees
- Delta ensures no duplicates even after failures.  
- Checkpointing is required.

# 4. Advanced Delta Lake Features

## 4.1 OPTIMIZE + ZORDER in Streaming Tables
- Compact small files generated by streaming.  
- Cluster data for faster queries.

## 4.2 VACUUM and Retention Policies
- Cleans old files from Delta log.  
- Default retention: 7 days.

## 4.3 Delta Log Internals
- Stores transaction history.  
- Contains JSON commit files and Parquet checkpoints.

## 4.4 Time Travel
- Query previous versions of a table.  
- Useful for debugging streaming pipelines.

## 4.5 Delta Constraints
- NOT NULL  
- CHECK  
- GENERATED COLUMNS  
- Enforce data quality at write time.

## 4.6 Delta Change Data Feed (CDF)
- Exposes inserts, updates, deletes.  
- Ideal for downstream replication.

# 5. Streaming Triggers

## 5.1 once
- Runs one batch and stops.  
- Used for deterministic batch‑like pipelines.

## 5.2 availableNow
- Processes all available data and stops.  
- Ideal for backfills.

## 5.3 Fixed Interval Triggers
- Example: `.trigger(processingTime="1 minute")`.  
- Standard micro‑batch mode.

## 5.4 When to Use Each
- **once** → deterministic batch  
- **availableNow** → backfills  
- **interval** → continuous ingestion
